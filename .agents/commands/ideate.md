# Ideate

Brainstorm and prioritize what to build next. Use the `product-ideation` skill.

1. Read the project context first: `docs/ARCHITECTURE.md`, `docs/STATE.md`,
   `docs/features/*.md`, the design manifest, and the data model.
2. Propose candidate use cases / user stories grounded in what exists, each with
   a fit analysis (reuses vs. new, dependencies, risks).
3. Prioritize by rough impact × effort × confidence; recommend the next 1–3.
4. If I ask for market/competitor input, pull external signal via web search and
   keep it clearly separated from internally-grounded ideas (cite sources).
5. For anything I pick, output a buildable spec ready for `/add-feature`, or a
   design brief via `/design-brief`.

Propose, don't build. Text after the command is the theme/problem to ideate on;
add "external" or "market" if you want web research.
