# Scaffold KMP / Compose Multiplatform frontend

Goal: a repo that **builds for Android and Web on the first try**, with the
clean-architecture layering that lets features be added without rework. This
mirrors the proven layout used in production (see `references/MODULE_MAP.md`).

> The full reference layout, naming, and the "add a feature" recipe live in
> `references/MODULE_MAP.md`. Read it before generating modules.

## Decide the shape first

- **`kmp`** (default): `shared` + `composeApp` with `androidMain` + `wasmJsMain`.
- **`web`**: same modules but only the `wasmJs` target enabled in `composeApp`.
- **`web-react`**: only if the user explicitly wants React/Vite — then ignore the
  Compose specifics and scaffold a Vite + React + TypeScript app with the same
  layering (domain/data/ui), Supabase JS client, and the same design-token
  source from the `design-bridge` skill (tokens generate CSS variables instead
  of a Compose theme).

## Module structure (KMP/Compose — the default)

```
shared/            Pure business logic — NO UI, NO Android/platform deps
  domain/
    model/         data classes (platform-free, no @Serializable)
    repository/    repository INTERFACES only
    usecase/       one class per use case — the only entry from UI to domain
  data/
    remote/dto/    @Serializable DTOs (mirror Supabase JSON)
    remote/datasource/  Supabase data sources
    mapper/        DTO <-> domain (bidirectional)
    repository/    repository implementations
  di/              Koin modules (dataModule + domainModule + supabaseModule)

composeApp/        Compose UI — NO direct repo/datasource access
  commonMain/
    App.kt
    theme/         AppTheme, Color, Type  (generated by the design-bridge skill)
    navigation/    Screen (sealed) + AppNavigation
    di/            AppModule (ViewModels) + allModules = sharedModules + appModule
    presentation/  one folder per feature: <feature>/{UiState,ViewModel,Screen}
      components/   shared composables
  androidMain/     MainActivity (Koin init + setContent)
  wasmJsMain/      main.kt (Koin init + CanvasBasedWindow) + index.html
```

## Hard rules (enforced by the `conventions` skill)

- ViewModels call **use cases** only — never repositories or data sources.
- Use cases call **repository interfaces** only — never implementations.
- Domain models carry **zero** `@Serializable` / Android / platform annotations.
- All Supabase JSON shapes live as DTOs in `data/remote/dto/`, mapped before
  crossing the domain boundary.
- Adding a feature = domain model → use case → repo interface → DTO + mapper +
  datasource impl → ViewModel event + UiState field → Composable. In that order.

## Adaptive layout (don't skip — it's the recurring pain)

- Build mobile-first. Use `WindowSizeClass` (Compact / Medium / Expanded).
- Navigation adapts: bottom bar on Compact, navigation rail/sidebar on Expanded.
- Never assume a minimum width; every screen must work at ~360dp wide.
- Put the breakpoint logic in one place (`navigation/AdaptiveScaffold.kt`), not
  sprinkled per screen.

## Files to generate

Use the asset templates as the starting point (placeholders in `{{...}}`):

- `assets/settings.gradle.kts.tmpl` — root settings, modules, repos.
- `assets/libs.versions.toml.tmpl` — version catalog (Kotlin, Compose MP, Koin,
  ktor/supabase-kt, kotlinx-serialization, coroutines).
- `assets/gradle.properties.tmpl` — KMP/wasm flags, `android.enabled` toggle.
- `assets/shared.build.gradle.kts.tmpl`, `assets/composeApp.build.gradle.kts.tmpl`.
- `assets/index.html.tmpl` — wasmJs host page.

After scaffolding, verify both targets:

```bash
./gradlew :composeApp:assembleDebug -Pandroid.enabled=true
./gradlew :composeApp:wasmJsBrowserDevelopmentRun   # or wasmJsBrowserDistribution
```

## Config injection (no secrets in code)

The Supabase URL + publishable key arrive as **build-time** values, never
hardcoded. Read them from Gradle properties / env (`SUPABASE_URL`,
`SUPABASE_PUBLISHABLE_KEY`) and expose via a generated `BuildKonfig`/`expect`
config object. The `supabase-backend` and `github-cicd` skills supply the values.
